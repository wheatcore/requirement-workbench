# 后端需求开发流程

## 1. 理解和拆解需求

- 先读取用户提供的需求及仓库现有约定，列出可独立验收的功能点。
- 每项任务写明接口或服务行为、输入输出、错误处理、数据变更和验收方式。
- 将大需求拆成可独立实现、验证并提交的小任务；按依赖顺序排列。
- 需求缺少关键接口契约或业务规则时，明确指出缺口，不臆造确定结论。

## 2. 只保留后端范围

- 保留接口、服务逻辑、数据模型与迁移、权限校验、后台任务、后端性能和自动化测试。
- 页面、样式、前端状态和交互归入前端范围；若依赖前端联调，只记录接口契约和联调条件。
- 对跨端任务说明前后端边界，保证后端部分可以单独验收。

## 3. 逐项实现

- 遵守仓库现有架构、命名、错误码、日志、配置和数据库迁移约定，优先复用已有服务和组件。
- 对外接口保持兼容；需要破坏性变更时，在任务中写明迁移和调用方影响。
- 校验输入与权限，避免把凭据或敏感数据写进日志、提交或测试样本。
- 每次只完成一项任务，保留清晰的改动边界；必要时更新接口文档和迁移说明。

## 4. 验证与提交

- 运行项目适用的单元、集成、类型或构建检查；涉及数据库时验证迁移和回退路径。
- 对新增接口至少覆盖成功路径、无效输入、权限不足及关键边界。
- 一项任务验证通过后再提交一次，commit message 使用 `<type>: <subject>`，不要合并多个任务为一个提交。
- 本工作台负责 Git 暂存和 commit；交给本机 Codex 的编码步骤不要自行运行 `git add`、`git commit` 或 `git push`。

## 5. 收尾

- 汇总已完成任务、验证结果、提交记录与未完成的跨端依赖。
- 不自动推送远程分支。
